# M35 physical Mac validation

Status: **pending**. Run on a clean macOS account with the M35 development app, an external drive, a configured OneDrive File Provider folder and a phone. Record build SHA, architecture, macOS version, hardware and observed permissions. Use only synthetic/owned clips. Do not change M32 or deferred earlier-milestone results.

1. Start with phone transfer off. Check files appear only in the [documented paths](../platforms/macos-files-and-lifecycle.md#files-and-storage). Import a local Unicode/long-path clip using native selection; verify its SHA-256 is unchanged. Prepare playback, delete only the disposable cache, and rebuild it.
2. Configure only one watched capture folder. Put a clip in a different, unconfigured folder and confirm it is never scanned/imported. Add a slowly copying clip to the configured folder: import only after completion and stability. Restart and verify no duplicate asset/import job.
3. Import/watch a clip on an external drive. Disconnect, verify a recoverable offline state and retained records, reconnect, reauthorize through **Select folder again…** and confirm one import per version. Repeat while an import is active; the source hash must remain unchanged.
4. Revoke the app's Files and Folders access in System Settings. Confirm an access-required state; cancel reauthorization and confirm no change. Select the same folder and grant access; confirm recovery and preserved history. Selecting a different folder must be refused.
5. In OneDrive/File Provider, make a synthetic clip cloud-only. Confirm the watcher does not hydrate it and an explicit import explains download-required. Use Finder/OneDrive to keep it local, wait for download/stability, then confirm one import. Repeat with a cloud-only subfolder and offline network. Record actual provider/version and observed `SF_DATALESS` behavior.
6. Start a long render/import and a phone session, then physically sleep/wake. Verify phone listener/link are closed, watcher reconciliation has no duplicates, and incomplete jobs are recovered without false completion. Repeat quit/relaunch, host Force Quit, and worker SIGKILL; confirm no media tool keeps writing and partial staging is cleaned on relaunch. Native notification delivery is separate from injected coordinator tests.
7. On a clean account, open phone onboarding before enabling transfer. Test local-network permission allowed/denied and firewall allowed/denied, keeping the firewall enabled. Scan the code from a real phone on the selected private network, receive a synthetic clip, and verify an invalid/non-video upload is refused. The worker API must remain loopback-only. Confirm expiry and leaving the screen close the listener and invalidate the old link; received import staging is cleaned. Record which app/helper macOS attributes the prompt to. Repeat after M37 signing.
8. Quit the app, move the entire canonical library in Finder, reopen and choose it using **Choose existing library…**. Quit/reopen again; verify assets, jobs, projects and models are present. Cancel the picker and choose a non-library folder (including an unrelated SQLite database) to verify the prior choice and that database are kept unchanged. Disconnect the selected drive and restart: no empty replacement database may be created. Reconnect/select the same library to retry.
9. Use native Save panels for an export and diagnostics. Cancel once; no file should appear. Save to a Unicode external path; no existing file may be overwritten. Confirm diagnostics/logs contain no tokens or private paths before sharing a redacted result.

Record each step as Pass/Fail/Pending with evidence and remediation. A successful synthetic fixture, mounted disk image, CI runner or loopback client must not be recorded as physical-drive, provider, clean-account or real-phone proof.
